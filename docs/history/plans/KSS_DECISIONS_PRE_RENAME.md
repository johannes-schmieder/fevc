## KSS-STREAMLINE-1 decisions

Recorded 2026-08-17 after the owner stopped the fixed scale program.

1. Treat statistical validity, complete original-system residuals, numerical
   convergence, direct allocation safety, and caller-state restoration as
   hard command gates. Treat extra memory headroom, wall forecasts,
   performance targets, and scale extrapolations as advisory evidence.
2. Select the automatic solver structurally before estimator RNG. Retire
   pilot solves and projected-work withholding from the installed route.
3. Reuse the completed K1 comparison. Register the selected domain cursor by
   supported runtime, remove its legacy production probe cap, and do not make
   exact calculations depend on the randomized runtime.
4. Require fixed-seed invariance to row order, batching, and route within the
   observed IDs. Do not require pathwise equality after arbitrary ID
   relabeling. Keep `probeorder()` optional and allow ties.
5. Make each optional SCC run independent and explicitly resourced. A receipt
   records that run; it never unlocks another run. Typed estimator failures
   are collected diagnostics, while scheduler and direct capacity limits
   remain operational gates for the run that uses them.
6. Identify new SCC bundles and receipts as `KSS-STREAMLINE-1`. The active
   diagnostic bundle contains the installed command and its generic runner;
   it excludes the historical K1 and MATLAB scale harnesses.
7. Preserve KSS-SCALE-1 reports and failed jobs as historical evidence. These
   decisions do not qualify a scale, beta, production, public release, or
   software license claim.
