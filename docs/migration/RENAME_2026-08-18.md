# Package rename and CMG integration — 2026-08-18

## Boundary

The last commit before this migration is
`59aeb133470c0a27a5f543ca16fb8cdad5cc1a89`. The migration makes a hard cut:
the predecessor command is not installed as an alias, and the active package
has one public identity, `varcomp_kss`.

The mechanical identity mappings are:

| Predecessor | Current identity |
|---|---|
| command and package `kss_bc` | command and package `varcomp_kss` |
| installable tree `kss_bc/` | installable tree `varcomp_kss/` |
| private Mata prefix `kssbc__*` | private Mata prefix `vckss__*` |
| private Ado prefix `_kssbc_*` | private Ado prefix `_vckss_*` |
| private globals and build IDs `KSSBC_*` | private globals and build IDs `VCKSS_*` |
| legacy suite marker `KSS_BC` | suite marker `VARCOMP_KSS` |

Estimator names, KSS citations, numerical contracts, returned target names,
and `e(kss)` are not renamed. Historical reports, receipts, review packets,
and completed plans retain the identities and paths that were true when they
were created.

## CMG ownership and API boundary

CMG is now an internal component of the installable package rather than a
separate shared library. Its source, generator, oracle, tests, benchmarks, and
provenance records move from `shared/cmg` to `varcomp_kss/cmg`. The package
ships one generated runtime, `varcomp_kss/varcomp_kss_cmg.mata`, under the
private `vckss_cmg` namespace. The only other generated target is the
component's `cmgtest` test runtime.

The component API is 7 and the deterministic generator API is 4. These API
increments record the ownership and target-surface change; they do not change
the estimator, hierarchy algebra, solver tolerances, or numerical acceptance
contracts.
