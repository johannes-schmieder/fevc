## Qualification decision

**NOT PRODUCTION QUALIFIED.** The installed candidate passed the active
source-bound CZ24/CZ25 gates and the full 601-RHS CZ18 estimator. All three
independently scheduled two-times-CZ18 P20 stress calibrations then failed the
same typed automatic-routing gate before estimator RNG. The registered
projection certificate could not be created, and the full P200 stress job was
therefore not authorized or submitted. This unmet required gate controls the
decision even though the completed local and SCC checks pass.

No KSS-PROD-1 runtime is production-qualified by this report. Verified
candidate behavior includes the independent selector, installed CMG backend,
deterministic routing surface, Stata 18/19 installation, CZ24/CZ25 equality
gates, local four/eight-processor behavior, and full CZ18. Multilevel behavior
beyond CZ18 remains experimental. Probe sharding is unsupported, SCC MP8 is
unavailable, and PPML integration and econometric inference are outside scope.

## Runtime and scientific contract

The candidate runtime is Stata/Mata only. Python and shell are used for
deployment, validation, and SCC orchestration; MATLAB is a descriptive
benchmark and retained-sample comparator. None is a runtime dependency of
the public `kss_bc` command.

The candidate implements deterministic leave-out sample construction,
deletion-unit graph pruning and bridge removal to a fixed point, worker and
firm variance, worker--firm covariance, and total variance. Its production
finite-projection correction uses coefficient one on the mixed fourth moment.
Maintained MATLAB uses the legacy coefficient-two correction and a different
parallel probe stream, so corrected MATLAB estimates are descriptive rather
than an equality oracle.

The installed candidate supports exact, diagonal B1, bounded dense-terminal
CMG, and multilevel CMG routes. Routing and any admissible fallback occur
before estimator probes are consumed. Forced CMG does not fall back. Every
accepted iterative RHS must pass a recomputed complete original-system
residual check.

## Concurrency and timing interpretation

Independent routes, repetitions, datasets, and processor experiments may run
concurrently after their shared input is fixed. Concurrency does not by
itself establish contention or explain a timing difference. Hostname, queue,
node class, command time, qacct wall, CPU, and RSS are descriptive covariates.
Any P40-below-P20, warm-above-cold, or cross-host reversal must be labeled
`UNEXPLAINED_VARIABILITY` unless separate evidence establishes a cause.
Calibration admission uses registered robust summaries and conservative
envelopes, not a post hoc causal adjustment.

## Unresolved Stata/Mata limitations

- The SCC Stata modules expose only four actual processors. Eight-processor
  production behavior must therefore be documented with local MP8 evidence;
  it cannot be inferred from an eight-slot SCC request.
- Large multilevel CMG remains bounded by Mata memory allocation, sparse graph
  traversal, matrix-operation throughput, and convergence. Full CZ18 passes,
  but the registered connected two-copy graph defeats both automatic-route
  pilot backends before RNG on every repetition. The current evidence does not
  isolate whether B1 convergence, CMG convergence, or the complete-residual
  portion is decisive because failed route output does not retain per-pilot
  status and residuals.
- A dense terminal remains bounded. No result may justify an unbounded dense
  factor or hidden regularization.
- MATLAB internal core timings and Stata command timings measure different
  boundaries. End-to-end comparisons must retain startup, input preparation,
  pool, MEX, serialization, and scheduler accounting separately.
- Maintained MATLAB corrected estimates are not a scientific equality target
  because its finite-projection formula and probe stream differ.
- Any remaining performance gap after the active experiments must be labeled
  as measured Stata/Mata cost or unresolved, rather than attributed without
  evidence.
