\begin{abstract}
This report compares the public VCkss Mata route, the qualified VCkss Rust
\texttt{CMG\_FULL\_V2} route, and maintained MATLAB \texttt{LeaveOutTwoWay}
over four graph families, five stored-row counts, and 1, 2, 4, 8, and 16
target-core cells. Rust and MATLAB use the full target; Stata and Mata use
1, 2, 4, 4, and 4 effective processors. Each cell has three position-balanced
seed repetitions. Within
every SCC task, all three routes run sequentially on the same scheduler-assigned
host, so paired route ratios remain comparable without waiting for a particular
node. Primary outcomes are complete estimator command time and peak summed
process-tree resident memory during the estimator phase. The evidence contains
300 same-host tasks and 900 fresh-process estimator calls.
\end{abstract}

\section*{Which route should I use?}

There are \CompleteCells{} complete, rankable graph--size--core cells.
VCkss--Rust is fastest in \RustFastest{}, VCkss--Mata in \MataFastest{}, and
MATLAB in \MatlabFastest{}. These counts are a map of the measured grid, not a
general language ranking. Use the cell-specific curves and guidance files:

\begin{itemize}
  \item Use \textbf{VCkss--Rust} for the qualified match-deletion JLA tuple
        when its plugin is available and its receipted memory fits the budget.
  \item Use \textbf{VCkss--Mata} when source-only portability, inspection, or
        unsupported Rust options dominate speed.
  \item Treat \textbf{MATLAB} as a maintained cross-package comparator with a
        distinct RNG and numerical policy, not as an identity oracle.
  \item Prefer the smallest effective core count within 10\% of the route's
        measured maximum when additional cores buy little speed. That maximum
        is four for Mata and 16 for Rust and MATLAB.
\end{itemize}

VCkss omits \texttt{tolerance()}, retaining production defaults of $10^{-10}$
for fit solves and $10^{-6}$ for randomized probe solves. The strict Rust call
must return \texttt{CMG\_FULL\_V2}; the Mata call uses explicit
\texttt{backend(mata) rng(stata)}. Successful VCkss calls must pass the complete
original-system residual, accounting, target identity, \texttt{e(sample)},
data/RNG/sort restoration, memory, route, and lifecycle gates. Rust--Mata
corrected targets use the independent-probe envelope
\[
 |\widehat\theta_R-\widehat\theta_M| \leq
 \max\left\{10^{-8}\max(1,|\widehat\theta_R|,|\widehat\theta_M|),
 6\sqrt{\mathrm{MCSE}_R^2+\mathrm{MCSE}_M^2}\right\}.
\]
MATLAB must return finite targets, its accounting identity, the registered
retained rows, and an accepted numerical status, but target gaps are descriptive.
The high-target Rust--Mata cells compare full-target Rust with capped four-core
Mata. They are paired availability comparisons, not equal-core scaling claims.

\section{Measurement details}

Each SCC job runs one graph--size--target-core--replicate cell and all three estimators
sequentially on the same scheduler-assigned host. Order rotates across
repetitions. Jobs request 16 bound slots in project \texttt{welfgr} without a
fixed queue, CPU model, or exclusive-node constraint. \texttt{taskset}
restricts each fresh process tree to its registered role-specific subset. Rust
and MATLAB use the full target; Stata and Mata use at most the first four CPUs.
Stata, Rust, MATLAB pool identities, and the Linux process monitor independently
verify these counts and subsets. Host, CPU model, and affinity are receipted. Paired
within-task ratios are primary; absolute timing and cross-core scaling across
different CPU models are descriptive unless shown for a homogeneous stratum.

Primary time is the estimator invocation measured inside the application.
Secondary time covers fresh-process launch through validated output. Import,
pool startup/teardown, and one-time plugin/MEX compilation are separate.
Primary memory is the 250-ms sampled summed process-tree RSS between estimator
phase markers; full-process RSS, GNU time, scheduler \texttt{maxvmem}, and
VCkss forecast/admitted/retained memory are distinct receipts.

\subsection*{Exact invocation contract}

The literal per-task values for \texttt{SEED}, \texttt{MEMORY}, target and
role-effective cores, CPU affinity, and execution order are in
\path{task_manifest_300.tsv}. Each call runs in a fresh process restricted by
\texttt{taskset}; VCkss deliberately omits \texttt{tolerance()}. Preparation
hashes a benchmark-only Ado adapter that supplies full-target Rust threads
through the existing internal boundary while keeping Stata at no more than
four processors. This does not change the public command or installed package.

\section{Limitations}

The benchmark is synthetic, uses one qualified JLA tuple, and covers the Linux
SCC hosts selected by the scheduler. Windows is deferred. Graph degree changes
worker and firm counts at fixed rows. MATLAB's RNG, tolerance, and finite-
projection details differ. Heterogeneous CPUs limit unstratified absolute-time
and cross-core claims, even though route ratios are paired within task. The
eight- and 16-target Rust--Mata ratios use unequal effective core counts by
design. Results guide choices only within the observed graphs, sizes, core counts, memory
envelopes, versions, and scientific acceptance rules.
